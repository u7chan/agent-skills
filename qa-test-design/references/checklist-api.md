# API実装向けチェックリスト

REST / GraphQL / RPC エンドポイント、サーバーサイドのハンドラー／ユースケース層に当てる観点リスト。
`qa-test-design` のチェックリスト照合で参照する。

## 入力検証
- [ ] 必須パラメータ欠損で 400 が返るか
- [ ] 型違反（数値に文字列）で 400 が返るか
- [ ] 文字数・件数の上限／下限の境界
- [ ] 配列の空 `[]` と未指定の違い
- [ ] null / 空文字 / undefined の挙動の違い
- [ ] 不正な日付フォーマット、未来日／過去日の制限
- [ ] 数値の負数／ゼロ／極端値（INT_MAX、Infinity、NaN）
- [ ] エンコーディング（UTF-8、サロゲートペア、絵文字、ゼロ幅文字）
- [ ] SQLインジェクション／コマンドインジェクションを誘発する文字列

## 認証・認可
- [ ] 未認証で 401 が返るか
- [ ] 認証済みだが権限なしで 403 が返るか（404 で隠す方針なら 404）
- [ ] 他ユーザーのリソースに対する操作（IDOR）
- [ ] トークン期限切れ／改ざんで弾かれるか
- [ ] スコープ・ロールの境界（読み取り権限で書き込みを試す）

## 冪等性・整合性
- [ ] 同一リクエストの二重実行で副作用が二重にならないか（冪等キー）
- [ ] 競合（同時更新）の挙動：楽観ロックの 409、最終勝ちの方針
- [ ] トランザクション境界：途中失敗でロールバックされるか
- [ ] 外部APIや別DBへの書き込みが絡む場合の compensating action

## エラーハンドリング
- [ ] 想定外の例外で 500 と適切なログが出るか（スタックトレースを外部に漏らさない）
- [ ] バリデーションエラーが分かりやすい形で返るか（フィールド単位）
- [ ] レート制限の挙動（429）と Retry-After ヘッダ
- [ ] タイムアウト時の挙動（呼び出し側の長期待ち回避）

## レスポンス
- [ ] ステータスコードが仕様通りか（201 vs 200、204、202 など）
- [ ] レスポンスのスキーマ（必須フィールド、型、null許容）
- [ ] 件数 0 / 1 / N / 大量のページネーション
- [ ] ソート順の安定性（同値時の tiebreaker）
- [ ] 機微情報の漏洩（パスワードハッシュ、内部ID、削除済みフラグ）

## 副作用・外部連携
- [ ] DB 以外の副作用（メール送信、Webhook、キュー、ログ）の発火条件
- [ ] 外部API失敗時のリトライ・サーキットブレーカー
- [ ] 非同期ジョブ投入の重複・失敗・順序

## パフォーマンス・スケール
- [ ] N+1 クエリが発生していないか
- [ ] インデックスが効いているか（大量データでの応答時間）
- [ ] 一括エンドポイントの上限（bulk 件数）
- [ ] キャッシュのヒット／ミス、無効化のタイミング

## 観測性
- [ ] 重要操作に監査ログが残るか
- [ ] エラー時にトレースID／相関IDが付与されるか
- [ ] メトリクスが取れるか（成功率、レイテンシ、件数）

## 互換性・契約
- [ ] 既存クライアント（古いバージョン）からのリクエストで壊れないか
- [ ] スキーマ変更時に追加フィールドはオプショナルになっているか
- [ ] OpenAPI / GraphQL スキーマの更新漏れがないか
