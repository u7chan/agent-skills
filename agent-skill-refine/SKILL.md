# Agent Skill Refine

## 目的と原則

既存Agent Skillの意図、適用範囲、ユーザー明示要件を保ったまま、指示を必要最小限で明確かつ高密度にする。短さ自体を目的にしない。

## 必須ルール

- 対象Skillとユーザー要件から、目的、適用範囲、必須制約、成果物を一意に読み取れる場合だけ実行する。
- 重要な欠落、矛盾、複数解釈がある場合は推測せず、変更を止めて確認する。
- 曖昧な「このSkillを改善して」は意味保存範囲として扱う。仕様変更が必要なら停止して確認する。
- 期待する判断、行動、成果物、起動条件、停止条件、安全性を変えない。
- 本Skillの手順・依存として、他スキルを必須依存にせず、参照・起動・委譲しない。Herdr、サブエージェント、外部サービスにも依存・参照・起動・委譲しない。環境または上位指示が独立して要求するSkill適用は妨げない。
- scriptsやassetsの内容と動作を変更しない。

## 対象範囲

最初にAgent Skill一式と対象リポジトリの規約を調査する。

- `SKILL.md`
- `references/`と、本文から参照される文書
- `agents/openai.yaml`などのメタデータ
- READMEなど、対象Skillを掲載する必要な索引
- `scripts/`と`assets/`の構成、参照関係、外部依存。ただし変更は禁止する。

変更は指示文、参照文書、メタデータ、必要な索引更新に限定する。scriptsやassetsに改善が必要な場合は変更せず、根拠、改善案、影響範囲を示し、別工程の候補として報告するかユーザー判断を求める。

## ワークフロー

1. 依頼形態を判定する。
   - ファイル修正依頼: 対象ファイルを直接更新する。
   - レビュー依頼: ファイルを変更せず、問題、根拠、最小の改善案を返す。
   - 本文だけが渡された場合: frontmatterを含む完全な`SKILL.md`を返す。
2. 対象Skill一式、ユーザー要件、リポジトリ規約を読み、実行前提が一意か確認する。
3. 変更前の意味を、目的、起動条件、非起動条件、判断、行動、成果物、必須制約、禁止事項、停止条件、検証に分けて記録する。
4. 冗長な説明、曖昧な表現、同義反復、不要な構造を特定し、意味を変えない最小差分を決める。
5. 以下の重複規則と構成規則を適用して、許可されたファイルだけを更新する。
6. descriptionと本文の不一致は、意図が一意な場合だけ意味保存で整合させる。複数解釈がある場合は変更せず停止する。
7. 変更前後を対照し、意味保存の自己点検を行う。
8. 対象リポジトリに既存の非破壊的検証があれば実行する。追加依存や外部サービスが必要な検証は実行せず報告する。
9. 結果、主な変更、維持した重要制約、検証結果を簡潔に報告する。未解決事項、維持判断、別工程案は存在する場合だけ追加する。

## 重複の判断

- 同じ条件で同じ効果を持ち、配置にも意味がない場合だけ統合する。
- 既知の失敗対策、安全ルール、重要工程直前の再掲は、意味を否定できなければ維持する。
- 重複に見えても、適用条件、強度、時点、対象、例外のいずれかが異なる場合は維持する。
- 維持した重複に判断上の価値がある場合は、完了報告で理由を示す。

## 構成の判断

- 既存構成を原則として維持する。
- リポジトリ規約への適合、または明確に条件付きの詳細を分離する必要がある場合だけ`references/`へ分割する。
- 中核ワークフロー、必須制約、禁止事項、停止条件は`references/`へ移さない。
- 新しいresources、依存、外部連携を追加しない。

## 意味保存の自己点検

- [ ] 元の目的、適用範囲、ユーザー明示要件を維持した。
- [ ] 起動条件と非起動条件を狭めたり広げたりしていない。
- [ ] 期待する判断、行動、成果物、順序、停止条件を維持した。
- [ ] 安全ルール、失敗対策、重要工程直前の再掲を不用意に削除していない。
- [ ] scriptsとassetsを変更していない。
- [ ] 変更ファイルが指示文、参照文書、メタデータ、必要な索引だけである。
- [ ] 追加依存や外部サービスを導入していない。
- [ ] 実行した検証と、実行しなかった検証の理由を説明できる。
