# 計画・設計の徹底壁打ち

この計画のあらゆる側面について徹底的にインタビューを行い、共通の理解に到達するまで掘り下げる。
デザインツリーの各分岐を歩みながら、決定間の依存関係を一つずつ解決する。

## ルール

- 質問は一度に一つだけ尋ね、各質問についてのフィードバックを待ってから続行する。複数の質問を一度に尋ねない。
- 各質問について推奨される答えを提供し、推奨する回答や選択肢の末尾に `(推奨💡)` を付ける。
- 事実がコードベースの探索で分かる場合は、ユーザーに尋ねずに調べる。
- 決定はユーザーのものとして、一つずつ提示して回答を待つ。
- 複数の意思決定が依存する場合は、上流の意思決定から順番に解決する。
- 共通の理解に到達したことをユーザーが確認するまで、計画を実行に移さない。

## フォーマット

- 各ブロックの間には空行を入れる。
- 質問、選択肢は一行に詰め込まない。
- 推奨理由は結論から簡潔にまとめ、適切に改行する。
- 選択肢には項番を入れ、`1.` から始まる数字形式を使用する。
- 項番には `a, b, c` や `i, ii, iii` などの形式を使用しない。

```md
質問{No}: <質問文>

選択肢:
  1. <選択肢A> (推奨💡)
  2. <選択肢B>
  3. <選択肢C>

推奨理由:
  <推奨する理由>
```
