# 校正

文章上の明確な誤りだけを検出し、意味と構造を保った最小修正を示す。

## 対象

- 誤字、脱字、衍字
- 助詞の抜け、重複、取り違え
- 主語と述語、修飾語と被修飾語の明らかな不一致
- 句読点の抜け、過不足、文書内の明らかな不統一
- 同じ対象を指す語の表記ゆれ
- 閉じ括弧、閉じ引用符などの欠落
- 文法上の問題によって意味が通らない文

## 対象外

- 文体の好みに基づく言い換え
- 段落の移動、統合、分割や見出し構成の変更
- 主張の追加、削除、強化、弱化
- 事実確認や内容の妥当性評価
- 専門用語、製品名、識別子、命名規則の変更
- 意味が通る範囲の細かなスタイル差

対象外の改善が有用でも、校正結果へ混ぜない。必要なら「校正範囲外の提案」と明示し、ユーザーが求めた場合だけ示す。

## Markdown とリテラルの扱い

- コードブロック、インラインコード、URL、ファイルパス、コマンド、識別子、記号列を保護する。
- 見出し、表セル、引用、リスト内の自然言語は校正対象に含める。
- Markdown 記法そのものは変更しない。記法の修正依頼が別にある場合だけ扱う。
- リテラルか自然言語か判断できない文字列は変更せず、必要なら確認事項にする。

## 手順

1. 文書全体を通読し、文体、用語、Markdown の境界を把握する。
2. 保護対象を確定し、自然言語部分を点検する。
3. 候補ごとに、誤りを客観的に説明できるか確認する。
4. 原文との差が最小になる修正案を作る。
5. 修正によって意味、構成、判断の強さが変わっていないか再確認する。

辞書や文脈だけでは断定できない表記は、誤りとして扱わない。修正の必要性は「好み」ではなく、文法、文書内整合、読解可能性から判断する。

## 完了条件

- 指摘が文章レベルの明確な問題に限られている。
- 修正箇所と理由を一対一で説明できる。
- 原文の意味、構成、論調を変えていない。
- 保護対象を変更していない。
- 問題がなければ余計な改善提案を加えていない。
