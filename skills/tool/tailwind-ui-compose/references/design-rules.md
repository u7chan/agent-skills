# Design Rules

このファイルは `tailwind-ui-compose` の詳細ルール集です。
画面を設計または実装する前に読み、最終確認でも参照する。

## 1. 最優先原則

### 構成から始める

- パーツではなく画面全体の構成から決める。
- 先にセクションの役割を定義する。
- 情報階層が決まるまで、ボタン、カード、バッジ、パネルを散らさない。

### 1セクション1ヒーロー

- 各セクションに強い主役を1つだけ置く。
- 強調は色より先に、余白、サイズ、コントラストで行う。
- 同じセクションで複数要素を競わせない。

### 開いたレイアウトを優先する

- 必要以上に中央の小さな箱へ閉じ込めない。
- 広がりが必要な画面では、メインエリアを広く使う。
- 全幅セクションは外枠パネルへ押し込めない。

### 一貫性を守る

- 余白、書体、サイズ、色、角丸のルールを画面全体で揃える。
- セクションごとに別の見た目ルールを増やさない。
- ひとつの世界観を維持する。

### 最初からレスポンシブで考える

- デスクトップと狭い画面を同時に考える。
- 横並びは自然に縦積みへ落とす。
- 狭い画面では装飾より優先順位と可読性を守る。

## 2. 強い禁止事項

- カードグリッドを標準パターンにしない。
- 強いシャドウで階層を作らない。
- 強いグラデーションを複数箇所へ置かない。
- 全幅セクションを細い内箱へ閉じ込めない。
- 小さなチップ、バッジ、アイコン、コントロールを密集させない。
- 余白にランダムな値を使わない。
- 1セクションに複数ヒーローを置かない。
- 濃い背景装飾を重要テキストの裏へ敷かない。
- コンポーネント先行でレイアウトを組まない。

## 3. カードと囲いの扱い

### カードをデフォルトにしない

- 直接操作や明示的グルーピングが必要な時だけカードを使う。
- 整って見せるためだけにカードで包まない。

### 代わりに使うもの

- `section`
- カラム
- ディバイダー
- 余白
- 微妙な背景差

### 囲いより構造を優先する

- まず整列と間隔で整理する。
- それでも関係性が弱い時だけ最小限の囲いを足す。

## 4. Tailwind 実装ルール

### 基本

- Tailwind utility を基本の表現手段にする。
- `tailwind.config` や既存トークンがあれば先に使う。
- arbitrary value を乱用しない。
- クラス列は読める長さと規則性を保つ。

### 使うべき基礎プリミティブ

- `flex`
- `grid`
- `gap-*`
- `px-*` `py-*`
- `max-w-*`
- `border-*`

### 避けるべき実装

- レイアウト調整のためだけの過剰なネスト
- 必要性の薄い absolute positioning
- `shadow-lg` `shadow-xl` 常用
- `rounded-*` のサイズ混在

### 影と境界

- 影より `border` `bg-*` `divide-*` `space-*` を優先する。
- 階層は面差と余白で表現する。
- どうしても影が必要な時だけ、ごく弱く使う。

## 5. タイポグラフィ

### 先に体系を定義する

- font family
- font size scale
- font weight scale
- line height
- text roles

### 役割を固定する

- page title
- section title
- body text
- supporting text
- meta text
- label text

### 推奨スケール

- `text-4xl` `text-3xl` `text-2xl` `text-xl`
- `text-lg` `text-base` `text-sm` `text-xs`
- `font-semibold` `font-medium` `font-normal`
- `leading-tight` `leading-snug` `leading-normal` `leading-relaxed`

### 禁止に近い注意

- 色だけで強調しない。
- 補助テキストを読みづらいほど小さくしない。
- 狭い領域で多すぎる文字サイズを混在させない。
- サイズと太さの強弱は節度を保つ。

## 6. 色

### 必須ロール

- primary color
- accent color
- neutral scale
- background colors
- text colors
- border colors
- success, warning, danger

### 運用ルール

- 強いアクセント戦略は1つに絞る。
- 鮮やかな色は優先度表現にだけ使う。
- 大半は neutral 系で構成する。
- semantic color は状態表示に限定する。

### 推奨トーン

- `zinc`
- `slate`
- `neutral`
- `stone`
- 既存の project token

### 禁止事項

- 虹色 UI を作らない。
- 同一ビューポートへ飽和色を多数置かない。
- 前景と背景のコントラストを弱くしない。

## 7. 背景

- 平坦な単色だけに頼らない。
- 使うなら弱いグラデーション、微細パターン、画像、面差のどれか1つを主役にする。
- 背景は雰囲気づくりに留め、本文より強くしない。
- 濃い背景の上に密な文章を置かない。

### Tailwind の方向性

- `bg-gradient-to-b`
- `from-*/*` `to-*/*` の低不透明度
- 中立色ベースの面差
- 弱い装飾要素

## 8. レイアウト

### セクション構造

- セクションを意味で分ける。
- 役割は `inform` `compare` `input` `guide` `act` のいずれかへ寄せる。
- 1セクションへ複数の強い目的を混ぜない。

### 余白

- 余白を装飾ではなく構造として使う。
- 縦方向リズムを揃える。
- タイトルとサブタイトル、セクション同士、ラベルと入力欄、項目同士の関係を一定にする。

### 整列

- 関連要素は同じ軸へ揃える。
- 開始位置を安定させる。
- 根拠のないオフセットを使わない。

### Tailwind 推奨パターン

- 外側: `px-6 py-10` `px-8 py-12` `lg:px-12`
- 内側: `gap-4` `gap-6` `gap-8` `gap-10`
- 幅制御: `max-w-5xl` `max-w-6xl` `max-w-7xl`
- グリッド: `grid-cols-1` `lg:grid-cols-2` `xl:grid-cols-12`

### 禁止事項

- すべてを窮屈な箱へ押し込まない。
- 似たセクションで padding をばらつかせない。
- 階層差が必要な時に全セクションを同格へ揃えない。

## 9. セクション構成

### 1セクション1目的

- セクションごとに主目的を1つだけ決める。
- `inform` と `act` のような強い目的を同格で同居させない。

### 1セクション1ヒーロー

- メインビジュアル、主要CTA、主要比較表、主要入力群など、錨になるものを1つだけ置く。
- それ以外は補助要素へ落とす。

### セパレーター

- 余白
- `border-t`
- `divide-y`
- 弱い面差
- カラム変化

### 避けるもの

- `rounded-2xl shadow-xl p-8` の反復
- ボーダーの中にさらにボーダー箱を重ねる構造

## 10. コンポーネント

### ボタン

- 1つのローカル操作群に primary は1つだけ置く。
- secondary は border または muted fill にする。
- tertiary は text button か低強度にする。

### フォーム

- 意味単位で入力を束ねる。
- ラベル、補助文、エラー文は簡潔に保つ。
- 装飾よりも余白とグルーピングで整理する。

### リスト

- カード積みより rows, grids, dividers を優先する。
- 反復項目の情報順序を固定する。
- 各行の軸を揃える。

### モーダルとドロワー

- 集中タスクだけに使う。
- 大きな画面構造を丸ごと詰め込まない。
- 本ページより目的を狭くする。

## 11. レスポンシブ

- モバイル安全な構造を基準にする。
- 重要情報を上へ置く。
- 横並びは `grid-cols-1 lg:grid-cols-2` や `flex-col lg:flex-row` で崩す。
- 幅が狭くなるほど装飾を減らす。
- タップ領域と余白を確保する。

### 禁止事項

- モバイルでデスクトップ密度を維持しない。
- 読みづらくても横並びを残さない。
- すべてを均等縮小せず、優先順位に応じて再配置する。

## 12. AI 判断ルール

迷ったら次の順で判断する。

1. 構成を明確にする。
2. 強調要素を減らす。
3. 装飾より先に余白と整列を使う。
4. 影より先に境界線と面差を使う。
5. アクセント色より先に neutral tone を使う。
6. 1セクション1ヒーローを守る。
7. レスポンシブを守る。

選択を迫られたら次を優先する。

- 足すより削る。
- 飾るより単純化する。
- 箱で囲うより分離する。
- 全部を強めるより周囲を静かにする。

## 13. 実装前チェック

- 全体構成は明快か。
- 各セクションの目的は1つか。
- 各セクションのヒーローは1つか。
- カード依存ではなく構造で整理できているか。
- 余白は一貫しているか。
- タイポグラフィは一貫しているか。
- 色は制御されているか。
- アクセント色は少なく意味があるか。
- 影は最小限か。
- 狭い画面でも強いか。
- 小さな UI 要素が多すぎないか。
- 画面全体が同じ世界観に収まっているか。
