# 6技法

QA観点を出すときは、対象に合わせて次の6技法を順に確認する。
各セクションは「適用」「該当なし」「補助」のいずれかで扱う。

## 1. 同値分割

同じ振る舞いをする入力グループに分け、各グループから代表値を選ぶ。

例: 予約人数が1〜4名のみ有効

| グループ | 代表値 | 期待結果 |
|---|---|---|
| 0以下 | 0, -1 | 無効 |
| 1〜4 | 2 | 有効 |
| 5以上 | 5, 100 | 無効 |

## 2. 境界値分析

境界の直前・境界・直後を確認し、`>=` と `>` の取り違えや off-by-one を捕まえる。

例: 有効範囲が1〜4なら、`0, 1, 4, 5` を含める。
数値、文字列長、日付、配列インデックス、ページ番号に適用する。

## 3. デシジョンテーブル

複数条件の組み合わせを表で整理する。
条件のAND/OR、ロール、機能フラグ、状態、プラン差分が絡むときに使う。

例:

| ログイン | 有料プラン | フラグON | 期待動作 |
|---|---|---|---|
| Y | Y | Y | フル機能 |
| Y | Y | N | 制限版 |
| Y | N | Y | アップセル |
| N | - | - | リダイレクト |

業務上ありえない組み合わせは、消した理由を短く書く。

## 4. 状態遷移テスト

状態を持つ対象で、正規ルート、不正ルート、到達不能状態を確認する。

- 状態を全て列挙する。
- 遷移できる／できないマトリクスを作る。
- 不正パスを最低1件は含める。

例: 下書き、申請中、承認済、却下、削除。

## 5. エラー推測

過去の障害や経験則から壊れやすい箇所を狙う。
必ず `danger-patterns.md` を読み、対象に当てはまるものだけ具体ケースに落とす。

代表例:

- 二重送信、戻る操作後の再送。
- タイムゾーン差分。
- null、空文字、undefined の混在。
- 全角、半角、ゼロ幅文字。
- 権限の抜け道。
- 通信失敗時の中途半端な状態。

## 6. チェックリストベース

対象種別ごとのチェックリストで漏れを補完する。

- API、サーバーサイド、ユースケース層: `checklist-api.md`
- 画面、フォーム、コンポーネント: `checklist-ui.md`

チェックリストは全部コピペせず、対象に該当する項目だけ抜き出す。
