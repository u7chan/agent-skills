# Agent Skill Design

## 概要

Agent Skillの目的、責務、起動条件、ワークフロー、成果物を設計し、実行可能な一式として作成または再設計する。

## 境界

- 新規Skillの作成と、既存ワークフローのSkill化を扱う。
- 既存Skillの要件追加、責務変更、起動条件の変更、全面再設計を扱う。
- 設計レビューでは、責務分離、起動条件、停止条件、構成、検証可能性を評価する。
- 意味保存型の簡潔化、短文化、同一効果の重複整理だけを目的とする作業は扱わない。

## ワークフロー

1. 依頼形態を新規作成、ワークフローのSkill化、仕様変更、全面再設計、設計レビューのいずれかに分類する。
2. ユーザー要件と対象リポジトリから、目的、適用範囲、入力、期待する判断・行動・成果物、必須制約を抽出する。
3. 重要な欠落、矛盾、複数解釈が設計結果を変える場合は、推測せず質問する。
4. 対象リポジトリの規約と既存Skillを確認し、命名、配置、メタデータ、索引、検証方法を特定する。
5. Skillの責務と非責務を定め、descriptionだけで起動条件と非起動条件を判別できるようにする。
6. 中核ワークフロー、必須制約、禁止事項、停止条件、成果物、完了条件を設計する。
7. scripts、references、assetsは反復性、決定性、段階的開示に必要なものだけを選ぶ。
8. 作成・変更依頼ではSkill一式を更新し、設計レビュー依頼ではファイルを変更せず指摘と改善案を返す。
9. ディレクトリ名、frontmatterの`name`、`agents/openai.yaml`、READMEなどの索引を同期する。
10. 対象リポジトリの非破壊的検証を実行し、差分と要件充足を確認する。

## 設計ルール

### 命名とメタデータ

- 名前は小文字、数字、ハイフンだけを使い、64文字以内にする。
- リポジトリ規約がある場合は、その命名規則を優先する。
- frontmatterには`name`と`description`だけを置く。
- `description`に機能と具体的な起動条件を含め、本文にしかない起動条件を作らない。
- `agents/openai.yaml`の表示名、短い説明、既定プロンプトを本文と一致させる。

### 本文とresources

- 指示は命令形で書き、実行順、分岐、停止条件、出力を明示する。
- Agentが一般知識から判断できる説明は省き、固有の制約と失敗しやすい判断を優先する。
- 中核ワークフロー、必須制約、禁止事項、停止条件は`SKILL.md`に残す。
- 長い例、条件付きの詳細、CLI/API仕様、トラブルシュートだけを`references/`へ分離する。
- 同じ処理を繰り返し実装する場合や決定的な再現性が必要な場合だけ`scripts/`を追加する。
- 成果物へ組み込むテンプレートや素材が必要な場合だけ`assets/`を追加する。
- 不要なREADME、変更履歴、補助文書、空のresourceディレクトリを作らない。

## 成果物

- 作成・変更依頼: 完成したSkill一式と、必要なメタデータ・索引更新。
- 設計レビュー依頼: 問題、根拠、影響、具体的な改善案。ファイルは変更しない。
- 本文だけを求められた場合: frontmatterを含む完全な`SKILL.md`。

## 品質チェック

- [ ] 責務と非責務が明確で、隣接Skillと起動条件が競合していない。
- [ ] `description`だけで機能と起動条件を判断できる。
- [ ] 期待する入力、判断、行動、成果物、停止条件が一貫している。
- [ ] 必須制約と安全ルールが実行箇所より前にある。
- [ ] resourcesは必要なものだけで、本文から参照できる。
- [ ] ディレクトリ名、`name`、`agents/openai.yaml`、索引が一致している。
- [ ] 対象リポジトリの検証が成功し、範囲外の変更がない。
