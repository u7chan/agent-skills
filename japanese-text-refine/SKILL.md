# 日本語文章の校正・推敲

依頼の意図に合う作業モードを選び、必要な reference だけを読む。

## 必須原則

- 依頼された範囲を越えて直さない。とくに校正モードでは、意味、構成、論調、話者の意図を変えない。
- 事実、数値、固有名詞、経験、根拠、成果、期限を推測で足さない。不足情報は質問するか `要確認` として分ける。
- 元文の敬体・常体、専門用語、組織固有の表記、対象読者に必要な硬さを尊重する。
- Markdown 記法、コード、URL、ファイル名、コマンドなどのリテラルを保護する。自然言語部分だけを対象にする。
- 「自然さ」のために不確実性、条件、制約、判断の強さを変えない。
- ユーザーが出力形式を指定した場合は、その形式を優先する。

## 作業モードを判定する

### 校正

「校正」「誤字脱字」「表記ゆれ」「文章チェック」など、文章上の誤りだけを求める依頼に使う。
`references/proofreading.md` と `references/output.md` を読む。

### 自然化

「AIっぽさを消す」「自然な日本語にする」「機械的な表現を直す」など、内容を保ちながら言い回しを改善する依頼に使う。
`references/naturalization.md`、`references/output.md` を読み、文書種別が明確なら `references/document-types.md` も読む。

### 執筆・推敲

新規執筆、リライト、構成整理、論証の強化、読みやすさやリズムの改善を求める依頼に使う。
`references/writing-and-revision.md`、`references/output.md` を読み、文書種別が明確なら `references/document-types.md` も読む。

複数の意図がある場合は、変更範囲の広いモードから処理し、最後に校正する。
依頼が曖昧な場合は、意味や構成を変えない範囲で進め、広い変更は提案として分ける。
各モードで変更境界に迷う場合だけ `references/examples.md` を読む。

## 共通ワークフロー

1. 依頼の目的、読者、文書種別、希望する変更範囲、出力形式を把握する。
2. 作業モードを決め、対応する reference を読む。
3. 元文またはユーザー提供の材料から、事実、主張、不確実性、文体、保護対象を抽出する。
4. 選んだモードの境界内で、影響の大きい問題から直す。
5. 内容の捏造、意味の変化、表記破壊、過剰修正がないか点検する。
6. `references/output.md` に従い、依頼に必要な成果だけを返す。

## Reference 索引

- `references/proofreading.md`: 校正対象、保護対象、最小修正の判定基準。
- `references/naturalization.md`: AI生成らしい癖の診断と自然化の手順。
- `references/writing-and-revision.md`: 構成、論証、読みやすさ、リズムを含む執筆・推敲規範。
- `references/document-types.md`: 技術・業務文の文書種別ごとの目的と重点。
- `references/output.md`: モード別の出力形式、要確認事項、最終品質チェック。
- `references/examples.md`: 校正・自然化・推敲の変更境界を示す短い例。
