# 実装ルールと品質チェック

## NGパターン

次のHTMLは作らない。生成前後にセルフチェックする。

- markdown の見出しをそのまま `<h1>` `<h2>` に変換しただけ
- 図が一切ない（文字だけ）
- 色分けがない（全部黒文字、全部同じ背景）
- 箇条書き（`<ul>` `<li>`）が大量に並ぶだけ
- ファイル:行 や 参照URL が `<ul>` の箇条書きで並ぶだけでテーブル化されていない
- 手順が `<ol>` のテキストリストで、ステップカード化されていない
- TL;DRカードがなく、結論が文章の途中に埋もれている
- **入力素材に書かれていない事実情報を視覚化のために創作している**（担当者名、Slack/チケットID、重大度ラベル、コード断片、URL、状態、KPI数値などを推測で埋める）。視覚化を成立させたい欲求が、ハルシネーションの最大の動機になる

## HTML作成ルール

- 保存先は `./output/{slug}.html` にする。
- 書き込み前に `mkdir -p ./output` を実行し、初回生成でも失敗しないようにする。
- `{slug}` は内容から英小文字とハイフンで分かりやすく命名する。
- HTML / CSS / JavaScript / SVG はすべて1ファイル内に含める。
- 外部CDN、外部フォント、外部画像、外部スクリプトは使わない。図はinline SVGで描画する。
- `viewport` metaを設定する。
- フォントは `system-ui`, `"Hiragino Sans"`, `"Yu Gothic"`, sans-serif を指定する。
- `prefers-color-scheme` でダークモードに対応する。
- 見出し階層は `h1`、`h2`、`h3` の順で自然に整理する。
- コントラスト、余白、行間は読みやすさを優先する。
- 色だけで意味を伝えない（アイコン・記号・ラベルで補強する。色覚多様性対応）。
- 画像を使う場合は `alt` を付ける。SVGには `<title>` または `aria-label` を付ける。
- JavaScriptを使う場合は、タブやアコーディオンなど必要な操作だけに限定する。
- 元のMarkdownをそのままHTMLへ逐語変換せず、人間が読む順序に再編集する。文字段落は最小限にし、視覚化コンポーネントに置き換える。

## GitHub Issue連携時の扱い

- Issue作成フローから呼ばれた場合は、確定済み `<proposed_plan>` と作成済みIssue本文を入力素材にする。
- Issue本文は実装者向けMarkdownとして尊重し、HTML側では人間のレビュー・共有用に**要約カード、比較テーブル、ステップカード、論点の状態テーブル**を前面に出す。
- Issue URLがある場合は、HTMLの冒頭または末尾に関連リンクとして置く。
- HTML生成の承諾が曖昧な場合は生成しない。直前の確認に対する `OK`、`お願いします`、`作って`、`yes` などの明確な承諾だけで生成する。

## 品質チェック

### 形式判断

- [ ] Markdownのままにするべき成果物を無理にHTML化していない
- [ ] HTML生成時にテンプレートを1つだけ選んでいる
- [ ] 選んだテンプレートの条件、構成、制約に合っている

### 視覚化（最重要）

- [ ] TL;DRカードが画面冒頭にあり、2〜3行で結論を言い切っている
- [ ] テンプレートに応じた標準視覚化コンポーネントが、素材で成立する範囲で入っている
  - single-screen-brief: カードグリッド + ステップカード
  - scroll-report: SVG図 1点以上 + 色分けテーブル + ステップカード + 根拠表
  - tabbed-workspace: SVG図 2点以上 + 色分けテーブル 2種 + Before/After + ステップカード + 根拠表
- [ ] 素材にない情報が必要なコンポーネントは、推測で作らず省略するか欠落情報として明示している
- [ ] 「成果物種別ごとの推奨コンポーネント」表の項目も、素材にある情報で成立する範囲で採用している
- [ ] 文字段落の連続でセクションを構成していない
- [ ] テーブルは状態色（done/gap/warn）で行が着色されている
- [ ] 手順は `<ol>` ではなくステップカードになっている
- [ ] ファイル:行や参照URLはテーブル化されており箇条書きではない
- [ ] 成功/失敗・完了/未実施が色 **と** ラベル/記号の両方で識別できる

### 素材忠実性（重要）

- [ ] 入力素材に書かれていない事実情報を、視覚化のために創作していない
- [ ] 情報が素材に無い箇所は、`不明 (要追記)` などで欠落を明示してある（黙って埋めない）
- [ ] 完了報告で「素材にない箇所をどう扱ったか」を1行で明示している

### 技術要件

- [ ] `./output/{slug}.html` に保存している
- [ ] 保存前に `mkdir -p ./output` で出力先を用意している
- [ ] 外部CDN、外部フォント、外部画像、外部スクリプトを使っていない
- [ ] CSS変数 `--ok / --ng / --warn / --accent` を定義している
- [ ] 矢印を使うSVGでは矢印マーカー（`arr-ok` / `arr-ng`）を定義している
- [ ] ダークモード、viewport、日本語向けフォント、見出し階層、コントラストを満たしている
- [ ] 画像があれば `alt`、SVGに `<title>` または `aria-label` を付けている
- [ ] JavaScriptはタブやアコーディオンなど必要な操作だけに限定している
- [ ] 人間向けに読む順序を再構成している
